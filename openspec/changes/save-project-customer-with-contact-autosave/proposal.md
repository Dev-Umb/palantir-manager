# Change: 项目内客户与联系人一体保存并支持联系人脱焦自动保存

## Why

项目编辑页当前把客户与联系人拆成独立保存动作。用户点击“保存客户”时只保存客户资料，当前联系人草稿不会一并保存；联系人输入框脱焦也不会落库，容易造成用户以为已经保存但实际丢失草稿。

## What Changes

- 项目内“保存客户”在一次事务中保存客户资料与当前非空联系人草稿。
- 已有客户的联系人姓名或电话输入框脱焦后，自动保存当前联系人及同屏客户资料。
- 自动保存使用串行队列；保存过程中产生的新修改必须在当前请求结束后继续保存，不能静默丢失。
- 联系人姓名为空时不创建空联系人，并保留草稿供用户补充。

## Scope Contract

### 必须改变

- “保存客户”同时保存客户资料和当前已填写联系人。
- 已有客户的联系人字段脱焦后自动保存。
- 客户与联系人组合保存必须具备事务原子性和明确反馈。

### 必须保持

- 现有管理员、业务员权限和项目关联规则保持不变。
- 独立联系人新增/修改接口和其他客户入口保持可用。
- 项目主表保存、筛选上下文、金额规则和历史记录保持不变。

### 允许隐藏

- 联系人手动“新增联系人/保存联系人修改”按钮不再作为必需入口，可由自动保存状态取代。

### 必须可见

- 自动保存中、保存成功和保存失败状态必须显示。
- 组合保存失败时必须保留客户和联系人草稿，供用户修正后重试。

### 禁止推断

- 不创建姓名为空的联系人。
- 不自动修改当前编辑联系人之外的联系人。
- 不批量修正既有客户、联系人或项目数据。

## Impact

- 扩展项目内客户 JSON 接口，允许可选的当前联系人数据。
- 修改项目客户维护组件的保存时机和并发控制。
- 不涉及 migration、数据库结构或历史数据变更。

## Evidence Boundary

- 本地测试和构建不代表生产已部署；上线后需验证真实项目页的脱焦保存与错误保留行为。
