# Design

## 事务化组合保存

项目内客户 `POST /project-customers` 与 `PUT /project-customers/{customer}` 接受可选 `contact` 对象。联系人对象只有在姓名非空时由前端提交。服务端在同一数据库事务中创建或更新客户与该联系人；更新联系人时验证联系人属于当前客户。任一校验或写入失败时整个事务回滚。

响应继续返回格式化后的 `customer`，并在组合保存联系人时额外返回 `contact`。既有不带 `contact` 的调用保持原行为，独立联系人路由继续可用。

## 脱焦自动保存队列

新客户尚无 ID 时，联系人脱焦只保留草稿，由“保存客户”组合创建。已有客户的联系人姓名或电话脱焦时触发组合保存。

前端使用同步锁和“仍有待保存修改”标记串行化请求。若保存进行中又发生脱焦或草稿变化，当前请求完成后按最新草稿再次保存。项目主保存按钮在队列清空前保持禁用。失败时停止自动重试并保留草稿，等待用户修改或再次脱焦。

## 空联系人

联系人姓名去除首尾空白后为空时，不向服务端提交 `contact`，也不创建记录。电话可为空。服务端仍将联系人姓名作为组合保存的必填字段，防止绕过前端创建空联系人。

## 非目标

- 不自动保存客户名称、等级、地址或备注的单独脱焦；它们随“保存客户”或联系人脱焦组合保存。
- 不改变客户和联系人对象的通用 CRUD 页面。
- 不删除既有独立联系人接口。
