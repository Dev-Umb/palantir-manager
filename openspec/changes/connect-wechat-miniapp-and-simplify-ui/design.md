## Scope contract
- 必须改变：真实后端认证/读取，小程序业务写入适配及简洁 UI。
- 必须保持：平台权限、项目范围、合同关联、金额口径、未填与零值区别、现有网页/Flutter 行为。
- 允许隐藏：装饰性口号、重复说明、首页低频功能；低频功能保留在“我的→业务工具”。
- 必须可见：当前账号、错误/加载/空状态、重要金额及其统计范围、写入确认和结果。
- 禁止推断：默认管理员等于免登录；Cookie 可跨域转发；没有权限等于零记录；本地成功等于已部署；只读验收允许标记已读或 AI 生成。

## Verified evidence
- 当前 Flutter 的 mobile/lib/environment.dart 指向线上平台；mobile/lib/api.dart 使用 Session Cookie、CSRF 和 Inertia。
- GET /login 的公开 HTML 含 Inertia v3 JSON script；取得 version 后，X-Inertia 请求返回 Auth/Login JSON。未提交真实账号密码。
- 无 version 的探测返回 409，因此网络层必须支持有界的版本恢复，不将其当作登录失败。
- 路由现有 /objects/{object}、/notifications 和业务写入返回 JSON；后续字段适配须以真实响应与现有 formatter 为准。

## Authentication and networking
增加专用 GET /miniapp/session、POST /miniapp/session、DELETE /miniapp/session 路由，使用 web session/CSRF 中间件，返回 JSON，不改变 /login 与 /logout 原契约。GET 可供未登录用户初始化 CSRF，会话响应只含必要的用户、角色、权限与版本信息及命名路由生成的 dashboardPath；POST 复用密码校验、登录限流和 session regenerate；DELETE 使会话失效。错误账号统一返回不泄露账号存在性的校验错误。仅专用会话路由调整为确定 JSON 错误；其他路由行为不变。

小程序使用 wx.request，并显式管理同源 Cookie、X-CSRF-TOKEN 和 Inertia version。只向固定 HTTPS 后端发送会话；外域附件不得携带登录 Cookie。会话默认仅驻留内存，首轮不存密码、不默认持久化管理员会话。注销/过期/切换账号时清空页面与请求缓存，取消或忽略旧会话在途响应。

登录默认用于现有管理员账号验收，但不硬编码管理员身份、共享内置账号或授予角色。管理员账号/密码由用户在最终登录界面输入；后端返回的权限才是依据。其他合法角色不应因本次开发被提升权限。

业务数据沿用现有 Inertia props/formatRecord，处理分页、筛选、关系显示标签、表单元数据和服务端校验。新建/编辑不得把未呈现字段清空；优先只更新已修改字段，必要的完整 payload 合并应基于服务端最新快照并按现有规则校验。避免客户端重新汇总分页列表冒充全量经营统计。

## Capability and field mapping
| 原 demo 能力/字段 | 新入口及数据来源 | 保留边界 |
| --- | --- | --- |
| 演示登录/退出 | 真实登录页、我的→退出；专用 JSON 会话接口 | 移除免登录与角色伪装，不存密码 |
| 业务员/管理员切换 | 我的展示后端角色 | 演示开关退出正式路径；不修改真实账号角色 |
| 重置演示数据 | 正式界面移除；测试夹具隔离保留 | 不提供线上清空业务数据功能 |
| 工作台统计 | 工作台紧凑金额区；复用后端统计 | 当前权限范围，全量口径，缺失不按零处理 |
| 最近项目/待办 | 工作台列表及通知入口 | 可见项目范围不变 |
| 项目搜索/筛选/刷新 | 项目页顶部搜索、状态筛选、分页 | 使用服务端筛选和总数，不只搜已加载页 |
| 项目编号、名称、状态、负责人 | 项目列表和详情概况 | 使用后端 code/payload/display 映射，未知状态不硬改 |
| 客户、多个联系人、地址 | 客户列表/详情及项目概况 | 保留客户与联系人区别；禁止显示无权关系信息 |
| 合同类型、金额、日期、数量、备注 | 详情→合同，逐份展示后端合同 | 一项目多合同，历史合同保留 |
| 合同附件 | 合同条目中的附件操作 | 受权下载预览；失败提示，不转发外域 Cookie |
| 合同额、已发生、已回款、未回款、末次回款 | 详情→回款 | 未回款沿用主档值；进度按平台口径；零分母不计算 |
| 新增/编辑项目与备注 | 项目页右上“新增”、详情“编辑” | 原权限/校验；写入前明确确认；保留未编辑字段 |
| 通知/未读/关联跳转 | 工作台通知入口、我的→通知 | 读取不自动标记已读；已读是明确写操作 |
| AI查询/报价示例 | 我的→业务工具→AI助手/报价 | 不在真实页面伪造回复；对接现有任务契约，未完成时明确待接入 |
| 文件选择/上传合同 | 我的→业务工具→上传合同 | 保留入口；真实上传需用户明确操作，人工确认识别结果 |
| 招采样例 | 我的→业务工具→招采参考 | 使用真实列表/详情/来源；未接入不得混入虚构公告 |
| 失败、无权限、加载/空状态 | 页面内对应状态与重试 | 401/419重登录、403无权限、网络错误可重试，不能混同空列表 |

## UI and UX
参考微信小程序设计规范和腾讯 TDesign 的 TabBar、Search、Cell、Form、Dialog、Toast、Empty 模式，但不新增组件库依赖。
- 保留“工作台、项目、客户、我的”四个标签，避免用户重新寻找入口。
- 工作台取消大幅品牌宣传；顶部标题与通知，紧凑金额概览、待办、最近项目。
- 项目页直接搜索；状态筛选放在搜索下；列表重点只展示名称、客户、状态和未回款，其他字段进入详情。
- 客户页直接搜索和单位列表；点击后见联系人与关联项目，不把所有信息挤在列表。
- 详情保留“概况、合同、回款”；编辑为明确按钮，表单仅在提交时显示相关字段错误并保留输入。
- 我的展示实际姓名/角色、通知、业务工具、退出；没有后台管理或演示模式开关。
- 白底、浅灰分区、单一蓝色主操作、易读字号和至少约44px点击区域；状态除颜色外必须有文本。
- 请求中有加载状态；查询结果计数与筛选相关；保存时防重复点击、失败保留草稿、成功更新列表和详情。

## Validation and release
本地测试覆盖 session/CSRF、失效、401/403/419/422/409、Cookie限制、旧响应丢弃、分页竞争、保存失败与保留字段；模拟器覆盖登录及主要路径。线上登录由用户输入凭据，只验收读取，禁止自动提交业务写入，含通知已读和AI任务。

后端更改必须独立提交，不混入工作区已有其他修改；quality gate、合并、部署、线上验收分别记录。未部署专用会话路由前，不能声称已完成线上接入。出现平台兼容问题时回滚新增会话入口和小程序构建，原有网页/Flutter保持原协议。
