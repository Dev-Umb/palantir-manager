## Context

系统使用 `business_objects` + `object_records.payload` 保存配置驱动的业务对象。现有 Dashboard 已按对象权限和 `ProjectVisibility` 展示数量、财务卡片、项目流转、风险提醒、库存/采购入口及最近项目。本变更只在该入口增加可视化读取层。

当前可用事实支持“截至当前”的经营快照以及少数带业务日期的趋势；它们不能还原未保存的历史变化。尤其是 `receivable.occurred_amount` 与 `receivable.paid_amount` 为累计快照，不能据此生成月度产值、月度回款、同比或环比。

## Scope Contract

### 必须改变

- 在现有经营大盘内增加只读经营 KPI、图表和风险行动视图。
- 仅从现有业务对象、记录、通知和权限读取并即时聚合。
- 明确每项指标的来源、公式、空值规则、统计时点、单位和权限范围。
- 图表必须提供可读数值、图例或文本摘要，并可下钻到既有对象入口。

### 必须保持

- 不新增、删除、修改任何数据表、字段、索引、业务对象定义、角色、权限或业务状态。
- 不产生业务记录、通知、审计日志、缓存事实或时间戳更新。
- 现有 `dashboard.view` 路由门禁、对象权限、`ProjectVisibility` 与请购的本人/审批人范围保持不变。
- 现有合同与回款提醒、通知中心、项目流转、采购申请、库存提醒、财务卡片和最近项目能力保持可达、可下钻。
- 现有 URL、route name、导航 key 与移动端主入口保持不变。

### 允许隐藏

- 用户缺少来源对象 `view` 权限的整个面板及其原始聚合数据。
- 已停用库存对象对应的统计。
- 依赖尚不存在业务对象的面板，例如没有 `tender` 时的招投标管线。
- 首屏以下继续保留的既有业务区块，但不得删除或替换。

### 必须可见

- 管理员显示“公司全量”；非管理员显示“我的可见范围”。
- 每个面板显示“截至”时间；演示稿显示“演示数据”。
- 比率显示分子、分母或口径说明，零分母显示“—”。
- 数据不完整时显示覆盖数量，例如“覆盖 8/10 个项目”。
- 获授权但无数据与没有权限必须是两个不同状态：无数据有空态，无权限时服务端不返回面板。

### 禁止推断

- 不把合同额、生产吨位或发货吨位命名为产值。
- 用户已确认第一版以 `receivable.occurred_amount` 作为产值口径，但页面主标签必须写“累计实际发生金额”，并在辅助说明中标记“产值口径”。
- 不从累计快照推导月度产值、月度回款、同比、环比或历史趋势。
- 不推断利润、毛利、成本、DSO、准时交付率、库存周转、料损、OEE、产能利用率、质量合格率或目标达成率。
- 不把 `dashboard.view` 解释为所有业务对象的数据权限。
- 不创造厂长角色、管理层级、目标值或红黄绿阈值。

## Audience and Permission Strategy

不新增任何权限或角色记录：

- `admin` 使用既有全量权限，页面标记“公司全量”。
- 其他用户进入同一 Dashboard，但每个面板必须先检查来源对象 `view` 权限，再使用既有范围约束进行聚合，页面标记“我的可见范围”。
- 只有 `dashboard.view`、没有任何对象查看权限的用户看到安全空壳，不收到对象数量、金额、分布或可推导的隐藏 props。
- 多角色用户沿用当前权限并集；下钻目标继续由目标路由服务端鉴权。
- 不做跨用户缓存，也不把完整公司聚合发送给前端后再隐藏。

| 面板 | 最低来源权限 | 既有数据范围 |
|---|---|---|
| 累计实际发生金额、回款、欠款 | `object.receivable.view` | 可见项目对应财务台账 |
| 合同到现金转化 | `contract` / `receivable` / `invoice` 对应 view | 各来源均先按可见项目收口 |
| 当前招投标管线 | `object.tender.view` | 当前角色已有 tender 范围 |
| 项目状态分布 | `object.project.view` | `ProjectVisibility` |
| 生产任务 | `object.work_order.view` | 关联可见项目 |
| 发货吨位 | `object.shipment.view` | 关联可见项目 |
| 风险提醒 | 来源对象权限 + 当前用户通知 | 不返回他人通知 |

## Information Architecture

### 页面壳层

- 沿用 248px 深色左侧栏、浅灰工作区、白色 surface、10px 圆角、细边框与轻阴影。
- 标题从“经营大盘”增强为“公司经营驾驶舱”；非管理员范围下显示“经营驾驶舱”。
- 标题右侧显示范围、统计时点和数据质量状态，不新增日期筛选器，避免让累计快照伪装成可按月回溯。

### 第一层：四项首要 KPI

| KPI | 公式 | 空值行为 | 历史能力 |
|---|---|---|---|
| 累计实际发生金额 | `Σ receivable.payload.occurred_amount` | 非数值不计并显示覆盖；没有有效值显示 `—` | 当前累计快照，不显示趋势 |
| 加权回款率 | 对每项目取 `base = occurred_amount > 0 ? occurred_amount : contract_amount`，再算 `Σmin(paid_amount, base) / Σbase × 100%` | `base` 或 `paid` 缺失的项目不进入分子分母并计入缺失；零分母显示 `—` | 当前快照，不显示趋势 |
| 投标中标率 | `count(status = 已中标) / count(status in [已递交, 已中标, 未中标]) × 100%` | 分母为零显示 `—`；其他状态不进分母 | 当前口径；不伪造历史确认日趋势 |
| 当前欠款 | `Σmax(base - paid_amount, 0)`，`base` 同回款率 | 不完整台账不按零计算；显示待跟进项目数和覆盖 | 当前快照，不显示趋势 |

次级数值“合同金额、已开票额、已回款额、活跃项目数”放入对应图表与文本摘要，不继续堆叠 KPI 卡。

### 第二层：风险提醒

- 保留现有“合同与回款提醒”在 KPI 后的优先位置。
- 风险卡继续链接到真实项目或通知中心；驾驶舱不新增风险状态、不写已读、不自动处置。
- 无风险时显示现有空态，不把“无权限”呈现为“无风险”。

### 第三层：四个可视化面板

#### 1. 合同到现金转化

- 图形：同一金额刻度的水平条形图，不使用面积误导或 3D 漏斗。
- 序列：合同金额、累计实际发生金额、已对账额、已开票额、已回款额。
- 直接来源：所有可见 `contract.amount`、`receivable.occurred_amount`、`receivable.reconciled_amount`、`invoice.amount(status=已开票)`、`receivable.paid_amount`。现有合同状态没有“已收到”，不得虚构该筛选值。
- 面板展示各数值覆盖率；不同来源不一致时只展示事实并标记数据差异，不写回修复。

#### 2. 当前招投标管线

- 图形：按当前状态排列的水平条形图，不声称为历史转化漏斗。
- 状态：跟踪中、已报名、已购标书、制作中、已递交、已中标、未中标；已放弃单独置灰。
- 数量始终可统计；预算金额仅汇总现有 `budget_amount`，并显示预算覆盖率。
- 中标率沿用既有 tender requirement：分母为已递交、已中标、未中标，分子为已中标。

#### 3. 项目状态分布

- 图形：按项目现有 `overall_status` 的环形图（扇形构成），圆心显示活跃项目总数，图例同时显示状态名称、项目数和占比。
- 现有状态仅为 `投标中 / 已中标 / 已拿到加工函 / 合同签署 / 已完成`；前四类计为活跃项目并进入环形图，`已完成`在同面板的非活跃状态摘要中单列。
- `overall_status` 为空或不属于上述配置值时进入“状态未维护”，在非活跃状态摘要中展示且不进入环形图。扇区数量之和、占比分母和圆心活跃项目总数必须一致。
- 这是当前快照，不显示状态耗时或历史迁移趋势，也不引入当前对象不存在的 `stage` 字段。
- 图形必须附带完整文本图例和数值摘要；颜色仅作辅助，不作为唯一信息载体。

#### 4. 生产与发货快照

- 生产任务按 `work_order.status` 计数；生产量使用 `production_qty_ton`，计划量使用 `weight`，两者都显示覆盖。
- 发货量使用 `shipment.qty_ton`；“有效吨位”指可解析为有限数值且 `>= 0`，其中 0 是有效记录并计入覆盖率、对总量贡献为 0。缺失、非数值、非有限值或负值不参与汇总，并分别计入缺失或数据异常提示；负值不得自行解释为退货或冲销。
- 月度折线图仅将有效吨位按可解析 `ship_date` 所在月份汇总。趋势覆盖分母为有效吨位记录数，分子为同时具有有效日期的记录数。
- `ship_date` 缺失或无效的有效吨位仍进入累计发货量，但不进入折线图，并显示“趋势覆盖 n/m”；无有效日期数据时显示折线图空态。
- 折线图明确标为“月度发货吨位”，不得表述为月度产值、生产量或回款趋势；累计快照字段不得用于反推历史增量。
- 生产量和发货量分别标为“吨”，不得换算为金额或与累计实际发生金额合并。

### 第四层：既有能力映射

| 现有能力 | 新布局承载位置 | 保留证据目标 |
|---|---|---|
| 顶部统计卡 | 首要 KPI + 对应图表摘要 | 原可见数据仍有等价展示 |
| 合同与回款提醒 | KPI 后的风险提醒区 | 通知中心和项目链接不变 |
| 项目状态推进 | 四个图表之后的全宽区块 | 使用现有五个 `overall_status` 展示当前步骤，不伪造额外阶段 |
| 采购大盘与提申请 | 项目流转以下原区块 | 入口和参数行为不变 |
| 库存提醒 | 项目流转以下原区块 | 已有获授权用户仍可见；已停用对象不新增统计 |
| 财务大盘 | 图表摘要 + 原区块 | 原始数值和权限范围保持 |
| 最近项目 | 页面下方表格 | “看项目”与记录内容保持 |

## Example Design

示例设计图位于 `assets/company-operations-cockpit-desktop.png`。图中金额、比例、项目数均为演示数据，并在页面头部明确标记；它只表达信息架构和视觉层级。示例中的项目构成采用环形图，月度发货吨位采用折线图，均附带文本口径。

桌面稿遵循当前设计语言：

- 画布 1440px 宽，左栏 248px，工作区净宽 1136px。
- 主背景 `#f2f4f7`，surface 白色，主色 `#246b95`，成功 `#2f8f6b`，警告 `#b7791f`，危险 `#c2413d`。
- 字体继续使用 Inter / PingFang SC / Microsoft YaHei；避免深色电视墙、霓虹发光、3D、玻璃态和装饰性仪表盘。
- ≤980px 时 KPI、风险、图表与业务区块单列；≤760px 时沿用现有固定底部导航。

## Empty, Missing, and Error States

- 无有效记录：数值显示 `—`，辅助文本显示“暂无可计算数据”。
- 有记录但关键字段缺失：显示有效聚合和“覆盖 n/m”，不得将缺失当作 0。
- 比率零分母：显示 `—` 与“分母为 0，暂不可计算”。
- 无来源权限：服务端不返回面板 key 和原始值，前端不渲染占位卡。
- 某来源对象不存在：省略依赖面板，其余驾驶舱正常展示。
- 聚合失败：该面板显示通用读取失败状态，不影响既有项目流转和快捷入口。

## Alternatives Considered

- 新增统计事实表或日报快照：拒绝，违反“不修改已有数据表且只基于原数据”的约束。
- 新建独立 `/cockpit` 页面：拒绝，与现有经营大盘重复并增加导航、权限和能力迁移风险。
- 给所有 `dashboard.view` 用户返回公司全量后前端隐藏：拒绝，会造成敏感数据泄漏。
- 使用合同额代替产值：拒绝，用户已确认以累计实际发生金额作为产值口径。
- 用 `updated_at` 或 `last_payment_date` 还原月度趋势：拒绝，累计快照无法还原历史增量。
- 深色霓虹“电视墙”样式：拒绝，与现有产品设计语言、可读性和日常办公场景不一致。

## Risks and Mitigations

- JSON payload 聚合可能随数据量增长变慢：实施时使用固定数量的服务端聚合查询并保留查询上限测试；不通过新表或后台写任务规避。
- 来源字段缺失会让数值失真：每项指标携带覆盖信息，缺失不按零。
- 不同来源金额可能不一致：分别按固定事实源展示并标记差异，不静默归一或写回。
- 图表可能扩大权限：所有聚合在服务端权限收口之后进行，未授权 props 完全省略。
- 招投标 change 尚未进入稳定基线时面板不可用：以对象存在性和权限为条件，缺失时省略。

## Rollback

设计阶段只需删除本 OpenSpec change 与示例资产。未来实施若回滚，只移除 Dashboard 的只读 props、React 图表和对应样式/测试；没有数据库或业务数据回滚步骤。

## Evidence Boundaries

- L2 PHPUnit Feature：指标公式、空值/零分母、对象不存在、管理员全量、各角色受限、仅 `dashboard.view`、多角色并集、请求无写副作用、查询数量有界。
- L3 Vitest：图表数值/单位/文本摘要、授权空状态、未授权面板缺失、演示标签不进入生产、既有区块保留。
- L4 在线验证仅在部署后另行授权执行；本设计、测试或构建通过均不等于已部署或线上正确。
