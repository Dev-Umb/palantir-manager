## Why

生产项目数据已经集中维护在项目主档，但经营大盘尚未直接汇总项目主档中的已发生、已回款和未回款金额，也无法按负责业务员查看对应合计。管理者需要在不依赖已隐藏财务台账、不改变项目数据的前提下，实时查看这些金额。

## What Changes

- 在现有经营大盘新增项目主档金额区块，展示公司已发生金额总计、已回款金额总计、未回款金额总计。
- 在同一区块按项目 `business_owner_user_id` 对现有账号分组，展示每名有项目记录业务员的三项金额总计。
- 每个金额字段独立忽略空值或非有限数字，保留数值 0 和负数，并显示有效记录数与项目记录总数。
- 页面每 15 秒从数据库重新读取可见项目并刷新经营大盘数据；后台标签页沿用 Inertia 默认节流。
- 继续复用既有 Dashboard 路由、对象权限和 `ProjectVisibility`，不新增数据库结构、持久化汇总或写操作。

## Scope Contract

### 必须改变

- 经营大盘显示项目主档三项公司金额总计和按业务员分组的三项金额总计。
- 汇总数据来自当前数据库中的 `project` 记录，并自动刷新。

### 必须保持

- 现有驾驶舱 KPI、图表、提醒、项目推进、最近项目、路由、权限和下钻入口保持不变。
- 项目、客户、财务、招投标及账号数据均不得被写入或修正。
- 管理员与非管理员继续使用既有数据可见范围。

### 允许隐藏

- 用户无 `object.project.view` 权限时，整个新增金额区块不返回也不渲染。
- 没有任何项目记录的业务员不出现在业务员汇总表。

### 必须可见

- 三个公司总计、各业务员三个总计、各字段覆盖数量和刷新时间。
- 没有有效金额的字段显示“—”，不得伪装为 0。

### 禁止推断

- 不从合同、财务台账或其他对象补算项目主档金额。
- 不把空值、文本、无效数字当作 0；数据库中已有的有限负数金额作为真实记录参与合计。
- 不把未分配、账号不存在或已删除账号的项目虚构为某个业务员。
- 不合并同名项目或重复项目；每条项目记录独立计入。

## Impact

- 预计修改 Dashboard 的只读聚合、Inertia React 展示、样式及对应 PHPUnit/Vitest 测试。
- 不涉及 migration、配置字段、角色权限、业务对象元数据、队列、命令或线上数据清理。

## Evidence Boundary

- 本地 OpenSpec、测试、构建和质量门禁通过只证明开发分支行为，不等于已提交、部署或在线验证。
