## ADDED Requirements

### Requirement: 管理员安全删除单个用户

系统 SHALL 在“用户与权限”页面为具有 `rbac.manage` 权限的管理员提供单用户删除操作。删除 MUST 立即撤销目标账号的角色与登录能力，并 MUST 保留该账号关联的历史业务、AI、通知和审计记录。

#### Scenario: 删除普通用户

- **WHEN** 管理员确认删除一个非当前登录用户且该用户不是最后一个有效管理员
- **THEN** 系统 MUST 在单个事务中解除其全部角色、删除其数据库会话、软删除用户并记录操作者、目标用户快照与原角色；该用户 MUST 从 RBAC 列表消失且后续登录 MUST 失败

#### Scenario: 保留历史关联

- **WHEN** 被删除用户已创建业务记录、AI Run、站内通知或审计记录
- **THEN** 删除用户后这些历史记录 MUST 继续存在并保持原用户外键，不得因账号删除触发级联清除

#### Scenario: 无权限用户直接调用删除接口

- **WHEN** 不具有 `rbac.manage` 权限的用户请求删除其他用户
- **THEN** 服务端 MUST 返回拒绝响应且目标用户、角色、会话与历史记录 MUST 保持不变

### Requirement: 受保护账号不可删除

系统 SHALL 阻止管理员删除自己或删除最后一个有效管理员，并在 UI 与服务端返回明确原因。

#### Scenario: 管理员尝试删除自己

- **WHEN** 当前登录管理员对自己的账号执行删除
- **THEN** 删除按钮 MUST 被禁用且服务端 MUST 拒绝请求，账号和会话保持有效

#### Scenario: 尝试删除最后一个管理员

- **WHEN** 目标用户具有 `admin` 角色且系统中不存在其他有效管理员
- **THEN** 删除按钮 MUST 被禁用且服务端 MUST 拒绝请求，不得解除该用户的角色或登录能力

#### Scenario: 多管理员环境删除一个管理员

- **WHEN** 系统存在至少两个有效管理员且当前管理员删除另一个管理员
- **THEN** 删除 MUST 成功，并确保至少一个有效管理员保留

### Requirement: 最后管理员角色不可移除

系统 SHALL 在现有用户角色编辑入口同步保护最后一个有效管理员，防止绕过删除保护。

#### Scenario: 角色编辑移除最后管理员

- **WHEN** 管理员通过角色配置从唯一有效管理员移除 `admin` 角色
- **THEN** 服务端 MUST 拒绝更新并保留原角色；存在其他有效管理员时角色更新行为 MUST 保持不变
