## Scope contract
必须改变：新建项目直接填写客户，保存时自动创建/复用。
必须保持：项目编辑、已有客户和联系人选择、其他字段及权限。
允许隐藏：无服务端客户维护能力时的直接输入；直接输入新客户时暂不展示已有客户联系人选择。
必须可见：名称+地址匹配提示、共享资料冲突、保存状态和失败原因。
禁止推断：同名不同地址合并、静默覆盖、客户端先创建客户。
## Capability mapping
原客户关系选择 → 保留原选择器，选择后关闭直接填写模式。
原联系人选择 → 已选客户时保留原选择器；直接填写时可选填一个新联系人随项目事务提交。
新名称/地址/等级/性质 → Web customer_profile 对应同名字段。
原项目编辑、附件保留、其他关系字段 → 不变。
## Verification
测试新建/复用的提交契约、预检失败/冲突取消、显式覆盖、重复点击、会话变化、原关系选择及项目编辑。复用现有 PHPUnit 匹配/事务/冲突测试；完整质量门禁和 WXML 编译后先合并再上传。

## Superseding layout contract
必须改变：仅客户填写入口迁移到二级页面，主表单恢复改动前字段。
必须保持：项目草稿、原客户/联系人选择、随项目创建/复用、冲突确认，以及独立客户新增入口。
允许隐藏：主表单新增的客户资料字段；无权限用户的二级新增入口。
必须可见：客户选择页新增/编辑待保存客户入口、回填结果、二级页面“随项目保存”提示。
禁止推断：清空项目草稿、回退客户匹配事务规则、提前创建孤立客户、改变 Web。
字段映射：customerDraft.name/address/level/customer_nature/contactName/contactPhone 全部迁入 customer-create 二级页面（project 模式）；customer_profile 提交不变；主表单客户/联系人栏仅展示回填摘要。已有客户选择和清除必须清除待保存标记；取消二级页面不得修改项目草稿。独立入口的备注与即时保存保持不变。

## Salesperson flow refinement
参考 Web 业务员流程：先搜索已有客户、无匹配再填写、返回项目后一次保存。参考微信官方 WeUI 的原生导航、列表表单和明确主操作（https://github.com/Tencent/weui-wxss）；微信设计指南直连不可读取，不把镜像当作已核验官方现行规则。
项目主表单保持原样。客户选择页搜索随输入更新，已有客户点选即回填，新增时携带搜索词。二级表单默认只显示名称、地址、联系人、电话；等级/性质或备注进入“更多资料（选填）”，折叠不丢值。底部固定一个主操作，返回项目不刷新或清空草稿。不扩展改造其他业务页面。

可选资料采用同页短表单切换：基本资料与更多资料分别显示，避免长表单滚动；已有输入保存在 page data，切换不丢失。必填校验失败会回到基本资料显示错误。\n
