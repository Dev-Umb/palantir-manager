# Design

## Capability Mapping

| 当前能力 | 修改后的载体 | 数据/权限 | 回归证据 |
| --- | --- | --- | --- |
| 我的页面版本展示 | 版本行与检查更新入口 | 原生读取已安装 versionCode/versionName | 无更新、检查失败、手动重试 |
| 启动与登录恢复 | 恢复后异步检查，登录页也可检查 | 更新服务独立请求，不发送业务 Cookie | 更新检查失败仍能登录/恢复 |
| 已保存附件预览 | 文件卡片点击预览，长按/删除按钮标记移除 | 合同标识及服务端明确支持的附件标识 | 删除一份保留另一份及顺序 |
| 新附件追加 | 文件卡片追加与单个移除 | 本地 UploadFile 列表 | 同名文件只移除选中项 |
| 合同随项目保存 | 原事务保存并携带明确移除意图 | 实际服务端现有协议，待核对 | 失败保留草稿；无权限拒绝 |
| 三页签与全部字段 | 工作台一致的卡片分组与导航 | 原字段元数据及 can 标记 | 字段完整、只读保留 |
| 首次加载/保存状态 | 钢蓝加载骨架、重试、保存按钮进度 | 原请求生命周期 | 加载失败、重复提交防护、退出提醒 |

## Update Flow

复用现有 Android MethodChannel，不增加依赖。提议同源 HTTPS 静态 JSON 清单包含 versionCode、versionName、notes、apkUrl、sha256、sizeBytes、packageName；仅更高 versionCode 展示更新。不传业务认证信息、不跟随未知外域，不缓存业务权限。APP 启动每次进程仅自动检查一次；用户可稍后处理，手动检查可重试。

下载写入应用私有缓存，提供进度和取消；限制文件大小，下载完成校验大小、SHA-256、包名、版本和当前签名兼容性后交给系统安装器。系统要求安装授权时展示说明并可返回继续；用户取消不显示安装成功。安装权限声明和文件共享方式按 Android 官方文档核对后实现。暂不加入额外签名体系或更新后台。

## Attachment Flow

待上传附件按列表位置/实例移除，避免同名文件误删。已保存附件先确认，再保留可撤销的待删除项；点击预览不触发删除。提交只发送服务端支持的移除标识；未确认、未保存或失败不改已保存记录。合同删除仍为独立确认操作。三种附件分类保持，新增文件与移除同时提交仍保留其他历史文件。

当前 contractWritePayload 明确排除旧附件 URL；不得为删除而直接回传该 URL 数组替换原文件字段。先核对服务端协议；必要的后端兼容变更另行评审。

## Editor Visuals

复用 steel/ink/canvas 与 panel，项目标题与编辑状态形成简洁顶部区域。三个页签保留，字段按现有业务含义分组，不新增业务字段。保存区固定在安全区域，显示正在保存与结果；忙碌时阻止重复提交。初始加载采用有文案的脉冲骨架，失败明确重试，不显示空表单为已加载。动效尊重系统减少动画设置。

## Validation and Rollback

Flutter 测试覆盖更新版本判断、损坏清单、网络失败、取消、校验失败、安装拒绝；附件单项删除/撤销、追加与保存失败、权限与其余合同保留；页面字段、页签、加载/重试与草稿回归。原生测试覆盖包校验与安装交接。运行静态分析、OpenSpec 严格验证与质量门禁，在 1080×2340/420 dpi 模拟器验证。

仅清单发布或 APK 构建不作为更新成功证据；不声称生产保存、上传或安装已验证。旧包没有自动更新能力，第一轮升级仍需安装新 APK。撤回清单停止提示；客户端回退保留原后端接口和签名，回退安装能力依 Android 版本规则核对。

## Approved removal protocol

formatRecord 为合同增加 attachment_tokens（仅当前可见文件字段），顺序对应已投影的附件列表；token 为存储路径 SHA-256，不暴露原路径。removed_attachments 为三类附件键到 token 列表的映射。保存校验 token 属于该合同该字段；事务内锁定后再次校验。精确移除关联、保留其他文件并追加新文件；证据要求按移除后的数量验证，保留最后签署/加工函附件规则。原文件保留用于历史审计；未提交移除参数的旧客户端行为不变。PC 保留现有 AttachmentTray 预览，增加逐项移除/撤销和待上传移除。
