# Android 更新与项目编辑体验

## Why

用户要求解决三个问题：APP 缺少更新入口、项目编辑无法逐个移除合同附件、编辑页面样式与工作台不一致且加载反馈不足。

## What Changes

- 启动自动检查更新；我的页面手动检查。展示版本与说明，用户确认下载，校验包后打开 Android 系统安装；允许跳过，不强制升级。此交互已获用户确认。
- 已保存及待上传的单个合同附件提供长按和可见删除入口；已保存附件确认后标记待删除，可撤销，保存成功才提交生效。
- 项目编辑沿用工作台钢蓝色、圆角卡片和间距；三个页签、分组表单、固定保存区域、加载骨架与保存进度保持一致。

## Scope Contract

必须改变：更新检查/下载/安装入口，单附件移除，项目编辑样式和加载反馈。
必须保持：所有字段与权限、多合同、其余附件顺序、预览、追加、客户冲突确认、草稿、登录恢复和 Web 行为。
允许隐藏：低频只读信息折叠；系统安装交互仍由 Android 承载。
必须可见：当前/新版本、下载进度与失败、待删除与撤销、加载失败重试、未保存与保存结果。
禁止推断：移除草稿等于已保存删除、下载完成等于安装成功、接口缺失允许新增业务规则、查看权限等于编辑权限。

## Excluded Scope

不做强制更新、静默安装、应用商店集成、后台业务模块扩展或历史附件批量清理。不自动部署服务或发布更新清单。

## Implementation Preconditions

当前本地路由和控制器没有 APP 依赖的完整合同维护协议。实现保存后的附件删除前，必须核对实际服务端代码及可复用的单附件删除协议；不以客户端生成的下载 URL 作为文件删除授权。若服务端确实缺失该能力，先补充评审后再修改后端。
更新清单与 APK 的托管位置需核对现有发布配置；默认提议使用既有生产 HTTPS 同源静态目录，发布是单独的操作。

## Approved scope extension (2026-10-04)

用户更正选择并明确授权最小后端修改及 PC Web/APP 同步功能修改。新增合同保存参数 removed_attachments，以服务端生成的稳定文件 token 指定单附件移除；不直接删除原文件，不改变现有权限、审计与事务。旧客户端缺省参数保持追加行为。完整基线位于 /private/tmp/palantir-contract-archive-code，当前主目录没有对应模块；在基线保存原有脏修改，交付本轮独立差异补丁。
