## Why
用户已批准 Web 通过现有小程序绑定扫码登录：网页出码、小程序明确确认、网页进入同一个平台账号。

## What Changes
- Web 登录页新增微信扫码入口，保留邮箱密码登录和注册入口。
- 使用现有小程序 AppID 生成小程序码；登录挑战随机、短期、一次性，绑定发起浏览器会话。小程序必须主动确认或取消，扫描不直接登录。
- 小程序未登录时复用现有微信登录和固定绑定码流程，成功后返回电脑登录确认页，不新增账户或修改权限。
- 消费时重新校验绑定版本和用户有效性；解绑撤销扫码产生的 Web 会话，保持密码登录不受影响。
- 保持角色原有登录落点；错误、取消、失效可见。二维码仅含随机挑战，不含绑定码、会话或身份。

## Impact
涉及 Web 登录、现有微信绑定服务、小程序登录返回和新增确认页、路由和测试。使用现有共享缓存及锁，不增加表或依赖。不改变已有小程序业务入口、绑定码、手机号或权限规则。

## Approval
2026-11-09 用户“可以，进入开发”批准上轮描述的扫码确认方案；本文记录其实现边界。

用户随后澄清并再次确认：PC 页面生成二维码 → 手机扫码 → 打开鑫源昌小程序确认登录页。恢复本提案的小程序确认方案，不接入独立网站应用 OAuth。
