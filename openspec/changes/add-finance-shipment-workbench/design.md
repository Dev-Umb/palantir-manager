# Design

## Capability map
| 原能力/字段 | 新入口或保留位置 |
| --- | --- |
| 业务资料项目表 | 原路由与权限保留 |
| signed_weight 累计签收重量 | 保持原值及原入口；财务台账独立统计，不回写 |
| last_shipment_date | 保持原值及原入口；台账独立显示最大日期 |
| first_shipment_date | 原人工维护；财务台账不依赖或改写此字段 |
| 其他财务/合同字段 | 保持原值、原编辑权，不触发回款提醒 |
| 项目/业务员关联 | 使用现有 business_owner_user_id，不自动模糊匹配 |
| 原 Excel 所有内容 | 保存原文件与来源坐标、预检排除/待订正项；不执行文件内容 |

## Storage and consistency
每项目一个专用 ledger，JSON 保存有稳定 UUID 的单据及有序行；revision 比较交换，事务内保存台账与审计，不更新项目记录。完整明细计入汇总，未填写完整的行作为草稿保存且不计入。只有服务端返回成功才显示已保存。前端单请求串行，保留请求中产生的新编辑，失败保留输入并允许重试；409 不自动覆盖。

数量保留三位小数；单价两位；行金额以整数缩放计算到分后累计。空金额不推断为零价。金额只是本单小计，不回写项目金额。纯草稿、有效台账编辑及清空均不改变业务资料；清空仅使台账自身汇总归零。

## Imports
使用 Python xlrd/openpyxl 只读解析旧 Excel；用户已批准线上独立虚拟环境安装 openpyxl 3.1.5、xlrd 2.0.2，FINANCE_SHIPMENT_PYTHON 指定其解释器；执行参数为数组、超时、大小/行数限制、压缩容积限制。缺少解析器时明确失败，不伪装成功。CSV 使用同一归一化流程。先预检再确认；服务器保存预检结果与原附件，不信任客户端传来的明细。哈希避免同一项目重复文件导入。同项目相同日期、车号、品名、数量、单价的记录标为疑似重复待订正；修改文件再次上传不会静默重复计入。相同日/车不自动合并历史行：每个明确发货行暂为一单，连续无日期/车号行待订正。原始行保留。仅完整且明确标为吨的记录计入吨数；有品名和有效数量、仅缺单位/日期或为件台米的实际发货行进入可编辑明细，保持原值并待确认。退货冲减、疑似重复及非法数值仍保留在预检中。空模板行排除。来源行与 ledger_order_id 绑定，历史补导幂等追加，不覆盖已有编辑；待订正计数仅额外累加未进入明细的来源行。项目列表和详情必须提示未订正历史数据不在当前吨数中。

本地无现成业务库时，单独的本地导入命令建立以完整来源文件名为标识的待匹配项目；不捏造客户、不把近似名称合并。原始来源和待匹配标志可见。正式系统导入只关联已有项目 ID，不创建或改写项目、客户或业务员。先只读比对业务员、项目名、客户和文件内容；相似名称仅为候选，歧义需确认。

## Rollback and validation
部署必须先合并对应 PR，隔离其他未提交改动；只执行新增财务表迁移，不执行全量迁移、种子或本地造项目命令。不删原文件。独立本地库导入前备份。新增表的 down 可逆；回滚应用保留财务表与原附件，业务数据不做恢复性覆盖。L2 覆盖权限、草稿/有效值/非吨/并发/幂等及邻接字段；L3 覆盖直编自动保存、右键位置、末尾空白行、错误输入保留。最后运行 quality gate 与本地登录 UI 走查，各自报告证据。

## Excel grid refinement
项目详情以连续表格显示，同一来源工作表视为同一单据，不按车牌拆分；日期/车牌是行字段。历史行无此键时读取原单据字段，显式空值不得继承；不批量改写旧 JSON。来源工作表与手工记录分别小计；已知金额按行数量×单价累计，缺单位/日期仅阻止计吨。去除详情重复标题、统计卡和说明；密码提醒缩为修改密码入口，其他页面和权限规则保持。
