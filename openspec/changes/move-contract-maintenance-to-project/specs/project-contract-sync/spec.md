## ADDED Requirements

### Requirement: 项目保存原子同步合同集合

系统 MUST 在项目保存的同一数据库事务内，按稳定合同记录 ID 同步合同新增、更新和显式删除；任一明细失败时不得留下部分数据库结果。

#### Scenario: 同批新增、更新和删除

- **WHEN** 用户在一次项目更新中新增一份合同、修改一份已有合同并明确删除另一份合同
- **THEN** 系统 MUST 锁定项目及其合同集合、验证全部输入后完成三种操作
- **AND** 项目级合同汇总、流程与提醒 MUST 在批次后基于最终合同集合刷新

#### Scenario: 已有合同 ID 属于其他项目

- **WHEN** 请求携带不属于当前项目的合同 ID 或删除 ID
- **THEN** 系统 MUST 拒绝整个请求
- **AND** 当前项目、目标合同及其他项目合同 MUST 全部保持不变

#### Scenario: 项目客户与合同输入冲突

- **WHEN** 客户端尝试在嵌套合同中提交与项目不同的客户或项目引用
- **THEN** 系统 MUST 忽略客户端派生引用并仅使用父项目的 `customer_id` 与项目 ID
- **AND** MUST NOT 产生跨客户或跨项目合同

#### Scenario: 同步中途失败

- **WHEN** 合同集合中的任一步数据库验证或写入失败
- **THEN** 项目与本批合同数据库变更 MUST 全部回滚
- **AND** 系统 MUST 仅清理本次新上传且未被引用的文件，不得删除旧附件或无关附件

### Requirement: 项目同步复用既有合同业务规则

项目来源的合同写入 SHALL 复用既有合同编号、规范化、关系校验、审计、引用保护、项目汇总、财务/流程联动和提醒规则，不得另建一套口径。

#### Scenario: 新增补充协议后刷新项目

- **WHEN** 项目保存新增一份合法补充协议
- **THEN** 系统 MUST 生成既有 `HT` 规则的合同编号并写逐合同审计
- **AND** 项目合同编号、合同数量、合同金额、流程与提醒 MUST 与通过旧合同规则得到的结果一致

#### Scenario: 一批包含多份合同变化

- **WHEN** 一次项目保存改变多份合同
- **THEN** 系统 MUST 为每份实际变化保留审计证据
- **AND** 项目级汇总、流程与提醒刷新 MUST 基于最终集合执行且不得产生中间态结果

### Requirement: 合同表成为只读同步视图

合同表 SHALL 保留现有列表、搜索、详情、三类附件查看和导出能力，但 MUST 对所有角色隐藏人工写控件并由服务端拒绝直接合同新增、更新和删除。

#### Scenario: 用户打开合同表

- **WHEN** 现有获授权用户打开合同表
- **THEN** 系统 MUST 展示项目同步后的合同记录并允许搜索、查看详情、查看授权附件和导出
- **AND** 页面 MUST NOT 展示新建、编辑、删除或单元格编辑控件

#### Scenario: 管理员或持有历史合同写权限的用户直接调用接口

- **WHEN** 用户绕过界面直接请求合同创建、更新或删除接口
- **THEN** 服务端 MUST 返回 403 且不得改变合同、项目、审计、流程或提醒
- **AND** 历史合同权限键及合同读取权限 MUST 保持存在
