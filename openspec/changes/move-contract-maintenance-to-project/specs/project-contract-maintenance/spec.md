## ADDED Requirements

### Requirement: 项目主档维护多份合同明细

系统 SHALL 在项目新建、编辑和详情上下文中展示该项目的全部合同明细，并允许具有当前项目更新权限的用户维护零到多份合同；合同明细 MUST 继续持久化为现有 `contract` 记录，不得复制到 `project.payload`。

#### Scenario: 新建项目时录入多份合同

- **WHEN** 获授权用户新建项目并提交两份合法合同明细
- **THEN** 系统 MUST 创建一个项目和两条分别关联该项目的合同记录
- **AND** 每条合同 MUST 使用项目客户作为 `customer_id`
- **AND** `project.payload` MUST NOT 包含合同明细数组

#### Scenario: 查看既有项目合同

- **WHEN** 获授权用户打开已有历史合同的项目详情或编辑界面
- **THEN** 系统 MUST 从现有合同记录实时返回全部明细、系统合同编号及授权附件链接
- **AND** MUST NOT 要求历史数据迁移、复制或重新编号

#### Scenario: 无项目更新权限

- **WHEN** 用户可以查看项目但没有项目更新权限
- **THEN** 用户 MUST 只能查看其可见项目的合同明细
- **AND** 服务端 MUST 拒绝其合同新增、修改、删除或附件替换请求

### Requirement: 每份合同保留三类可累加授权附件

每份合同明细 SHALL 保留加工函、合同、对账单三类多附件集合；新文件 MUST 追加而非替换历史文件，文件类型、大小、数量、状态凭证和授权读取规则 MUST 与现有合同能力一致。

#### Scenario: 上传两份合同的附件

- **WHEN** 用户在同一项目提交两份合同并分别选择加工函、合同或对账单附件
- **THEN** 系统 MUST 将每个附件追加到对应合同记录及附件类别
- **AND** 项目详情与合同只读详情 MUST 返回各自的授权查看入口

#### Scenario: 编辑时未选择新附件

- **WHEN** 用户编辑已有合同但未为某附件类别选择新文件
- **THEN** 系统 MUST 保留该类别全部旧附件及其引用
- **AND** MUST NOT 将空输入解释为清除附件

#### Scenario: 附件验证失败

- **WHEN** 任一合同附件类型或大小不符合规则
- **THEN** 系统 MUST 以对应明细索引返回验证错误
- **AND** 项目和本批全部合同数据库变更 MUST NOT 提交

#### Scenario: 状态缺少对应附件凭证

- **WHEN** 用户把合同状态改为“已有加工函”却没有加工函附件，或改为“已签署”却没有合同附件
- **THEN** 系统 MUST 按既有合同规则拒绝整批项目保存
- **AND** MUST NOT 绕过现有合同状态推进约束

### Requirement: 合同删除必须是显式意图

系统 SHALL 只删除用户明确确认并提交到 `deleted_contract_ids` 的当前项目合同，不得根据合同数组缺失推断删除。

#### Scenario: 明细未随局部提交出现

- **WHEN** 项目更新请求未包含某条已有合同且没有提交其删除 ID
- **THEN** 系统 MUST 保留该合同及附件不变

#### Scenario: 用户确认删除一份补充协议

- **WHEN** 用户在项目合同编辑器明确确认删除一条属于当前项目的补充协议
- **THEN** 系统 MUST 删除该合同记录并刷新项目合同汇总、流程和提醒
- **AND** 同一项目的其他合同 MUST 保持不变
