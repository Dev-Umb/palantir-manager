## Scope contract

- 必须改变：项目内可完成无 AI 的合同附件上传。
- 必须保持：历史附件、合同字段、其他合同、权限、数据范围、金额空值与零值区别、现有 AI 上传。
- 允许隐藏：无合同维护权限的上传入口。
- 必须可见：目标项目及合同、所选文件、处理状态、失败原因、保存后的附件。
- 禁止推断：不得通过附件推断金额、日期、合同签署状态或替用户选择多份合同中的归属。

## Entry points and preservation map

| 现有能力 | 实现后入口或保留方式 |
| --- | --- |
| 项目概况、回款、编辑资料 | 原入口保留 |
| 合同明细与附件预览 | 原合同卡片保留，上传后刷新 |
| 项目合同页占位上传按钮 | 替换为各合同上传入口和新增合同并上传入口 |
| 我的 → 上传合同（AI） | 原入口及确认归档行为保留 |
| 附件存储、访问鉴权、审计 | 复用服务端现有机制 |

## Implementation approach

先检查所有相关调用及现有测试。复用现有附件选择、会话 epoch、防重复提交与错误展示方式；仅在现有 multipart 写入可保留并发合同字段时复用通用更新接口。否则使用窄范围追加接口，在锁内读取当前记录，复用存储和权限服务，保证其他字段不被旧快照覆盖。客户端显示权限不替代服务端授权。

已有合同上传不提交金额或状态修改。新合同由用户明确录入状态及必要资料，允许金额未知但必须满足现有附件证据规则。每次处理一个文件，逐个明确结果；不引入批量并发上传或自动重试机制。

## Alternatives

- 跳转 AI 上传：不满足用户明确要求，排除。
- 全量移植网页合同编辑器：扩大范围，排除。
- 将文件作为项目其他附件：丢失合同归属语义，排除。

## Risks and rollback

重点验证跨项目越权、并发覆盖、会话切换、结果不明重复上传与上传失败存储清理。移除新增入口及接口即可回滚功能；已保存的业务附件不得删除，继续使用既有预览入口。

## Evidence boundaries

本地测试、质量门禁、PR 合并、部署、模拟器和真机结果分别记录。不得自动上传真实业务文件作验收。

## Production upload configuration

生产默认请求体上限为 20 MB，新路径需要专用 Nginx location。仅匹配项目 UUID 下的 contract-uploads，沿用已有合同上传的 100 MB 文件及 101 MB 请求体限制，保持其他地址限制不变。部署前备份路由和 Nginx include，执行 nginx -t 后 reload；回滚恢复这两项备份并移除新控制器。
