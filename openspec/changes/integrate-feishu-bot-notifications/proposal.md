## Why

Palantir 的项目、招投标提醒目前只停留在站内通知，业务人员无法在飞书及时收到；同时，用户希望在飞书私聊机器人中复用 Palantir 的数据权限，快速查询欠款和项目进度。

项目回款提醒的业务口径进一步收紧为：项目处于“已拿到加工函”或“合同签署”状态，未回款金额大于零，且存在有效的末次回款日期。末次回款日期满一个自然月后首次提醒，之后每 15 天重复提醒；日期缺失或无效时不提醒。

## Scope Contract

### 必须改变

- 回款提醒资格改为 `overall_status` 属于 `已拿到加工函`、`合同签署`，`unpaid_amount > 0`，且 `last_payment_date` 存在并可解析。
- 回款提醒只以 `last_payment_date` 为锚点，满 1 个自然月时首次触发，之后每 15 天重复提醒。
- 站内项目和招投标提醒可异步投递到已绑定用户的飞书私聊。
- 飞书私聊文本或群聊中明确 @ 机器人的文本消息可创建一次 Palantir AI 查询，复用发起人的数据可见范围；私聊任务私聊回复，群聊任务回复原群。
- 飞书回调、入站事件、出站投递均可幂等重试并保留可审计状态。
- 项目回款飞书提醒改为卡片，突出项目标题，并显示负责业务员、回款进度、欠款金额及 Palantir 详情入口。
- 站内项目和招投标通知标记已读后归档并从通知中心列表隐藏，同时保留通知记录和审计证据。
- 飞书 AI 查询结果将 Markdown 标题、段落、列表和表格转换为原生卡片元素，不再把不受支持的 Markdown 表格和标题语法原样展示。
- 飞书 AI 助理可按发起人的 Palantir 数据权限，将一次明确查询的结果新建为飞书云文档或电子表格，并在原会话返回文件链接。
- 生产主机提供独立的 `lark-cli` 应用身份配置，用于云文档能力验证和机器人导出执行；不接入 OpenClaw。
- 飞书中已绑定且具有合同维护权限的用户可发送 PDF/JPG/PNG 文件，文件先进入受审计的私有暂存区，再通过精确且唯一的项目编号和合同编号追加到合同附件或加工函附件。
- 合同表中的合同附件和加工函附件必须逐个显示可鉴权下载入口。

### 必须保持

- 站内通知仍是事实来源；飞书失败不得回滚或删除站内通知。
- 回款提醒收件人、重复计数、末次回款日期变化后的锚点重置和欠款清零后解除逻辑保持不变。
- 投标、加工函、合同签署提醒的资格、节奏和收件人保持不变。
- Web AI 助理、项目权限、`ProjectVisibility`、对象权限和数据范围保持不变。
- 机器人查询只读，不提供新增、修改、删除或执行 AI 写入提案的能力。
- 对 Palantir 业务数据仍保持只读；新建飞书导出文件不得扩大查询结果或绕过发起人的数据权限。
- 招投标提醒及非回款项目提醒继续使用现有文本消息格式。
- 已读归档不得删除通知、改变飞书投递状态或阻止同一风险后续新 occurrence 重新进入未读列表。
- 私聊与群聊回复目的地、Typing 表态、事件幂等、失败回复和既有提醒格式保持不变。

### 允许隐藏

- 飞书未配置或用户未绑定时，不产生外部消息；站内通知继续正常工作。
- 未 @ 机器人的群聊、非文本消息及机器人自身消息不进入 AI 查询流程。

### 必须可见

- 出站投递记录显示待处理、已发送、跳过或失败状态、尝试次数、飞书消息 ID 和脱敏错误。
- 入站事件显示接收、处理中、完成、拒绝或失败状态，并关联创建的 AI Run。
- 真实飞书验证与本地模拟验证、部署和线上验证分别报告。
- 卡片财务字段缺失时显示待补充，不由通知层猜测金额或进度。
- 导出成功后必须显示文件类型、标题、导出行数和可点击的飞书文件链接；失败时必须返回脱敏且可行动的提示。

### 禁止推断

- 不增加邮件或短信发送；群聊结果只发送到任务来源群，不转发到其他群。
- 不把“已下加工函”误解为图纸下发；系统枚举映射为 `已拿到加工函`。
- 不以项目创建时间、更新时间、加工函日期或旧的回款提醒锚点代替缺失或无效的 `last_payment_date`。
- 不因接入机器人而放宽 Palantir 权限或允许财务写入。
- 不在本 change 中部署、修改生产数据或宣称线上已验证。
- 不读取、编辑、移动或删除任意既有飞书文档；第一阶段只允许新建本次查询的导出文件。
- 不以用户身份冒充创建文件，不要求用户 OAuth，除非后续明确要求访问用户个人云空间。
- 不根据项目名称、客户名称、文件名或模型猜测合同归属；项目编号或合同编号缺失、重复、冲突时不得写入。
- 不覆盖或删除合同记录中的既有附件；飞书上传只能追加。

## What Changes

- 调整项目回款提醒资格和唯一日期锚点，并将首次到期后的重复周期由 1 个自然月改为 15 天。
- 增加飞书用户绑定、入站事件和通知投递记录。
- 增加飞书 API 客户端、异步通知投递、回调验签、事件去重，以及私聊与群聊 @ 机器人消息处理。
- 增加只读飞书数据助理，复用 Palantir 查询工具和 AI Run 审计链路。
- 通知中心只展示未读项目和招投标通知；已读记录保留但归档隐藏。
- 将飞书 AI Markdown 回复解析为结构化卡片元素，并让 agent 避免生成飞书不支持的 Markdown 表格。
- 增加受权限约束的飞书云文档、电子表格导出工具和 `lark-cli` 进程边界；只新建导出，不操作既有文件。
- 增加飞书文件资源下载、私有耐久存储、精确绑定命令和附件审计；生产可切换到独立私有 TOS 桶。
- 合同数据表把多附件数量展示改为逐个可下载链接，同时保持后端对象权限与项目可见范围校验。
- 以 HTTP/AI/Queue fake 完成本地全链路测试；真实飞书消息在执行前再次取得确认。

## Capabilities

### New Capabilities

- `feishu-bot-integration`: 飞书通知投递、账号绑定、私聊与群聊 @ 机器人 AI 查询和交付审计。

### Modified Capabilities

- `project-payment-reminders`: 回款提醒按项目阶段、未回款金额和有效末次回款日期进入既有周期。

## Impact

- 新增三张集成表、一个公开回调入口、队列任务、飞书服务配置和只读 AI agent。
- 修改项目与招投标通知触发点，使其在站内通知提交后排队外部投递。
- 扩展 `ai_runs` 以记录来源及飞书回复上下文；Web 默认值保持兼容。
- 不新增第三方依赖，不把 App Secret 写入仓库、日志、数据库或测试夹具。
- 生产新增 `lark-cli` 可执行文件与应用身份配置；应用密钥通过部署环境/标准输入配置，不进入命令参数或代码仓库。

## Evidence Boundary

- 本地 PHPUnit 证明测试数据库、队列、AI fake 与 HTTP fake 的全链路，不证明飞书真实租户已收到消息。
- 经用户执行前确认后的单次真实发送只能证明指定机器人/账号当时可收消息，不等于生产部署。
- 本 change 完成后只准备部署清单；部署需另行授权。
