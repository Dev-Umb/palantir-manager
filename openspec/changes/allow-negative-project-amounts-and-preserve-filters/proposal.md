# Change: 项目金额支持负数并保留编辑前筛选状态

## Why

项目主档当前为所有数字字段附加非负限制，导致退款、冲销、调整等金额无法录入；数字保存精度不统一；在带筛选条件的项目列表中通过编辑弹窗保存记录后，服务端重定向到无查询参数的列表地址，清空了当前筛选上下文。

## What Changes

- 仅项目主档的金额字段允许录入负数，项目重量和回款进度等非金额数字继续遵守原有范围。
- 项目主档所有 `number` 类型字段在新建和编辑保存时四舍五入到两位小数，并在列表与详情中固定展示两位小数。
- 项目数字输入默认使用 `0.01` 步长。
- 编辑弹窗保存后返回原始列表 URL，保留搜索、筛选、排序、分页和当前记录上下文。

## Scope Contract

### 必须改变

- 项目主档金额字段接受有限负数。
- 项目主档 `number` 字段保存时四舍五入两位并固定显示两位。
- 带筛选条件编辑保存后仍停留在同一筛选结果。

### 必须保持

- 回款进度继续限制在 0 至 100，累计签收重量继续不得小于 0。
- 项目之外的招投标、合同、采购、生产、库存等对象数值规则保持不变。
- 既有搜索、筛选、排序、分页、权限、审计、项目汇总和实时刷新口径保持不变。

### 允许隐藏

- 空数字仍显示既有空态，不显示伪造的 `0.00`。

### 必须可见

- 项目金额输入可接受负号，保存后的项目数字显示两位小数。
- 保存后地址栏及筛选控件继续保留原查询条件。

### 禁止推断

- 不批量改写历史项目数据。
- 不允许项目非金额字段因本变更绕过既有最小值或最大值。
- 不把两位小数规则扩展到其他对象或 `range`、日期、文本字段。

## Impact

- 修改项目字段元数据、项目保存归一化、数字展示和更新重定向行为，并补充 PHPUnit/Vitest 回归。
- 不涉及 migration、数据库结构、权限、路由或生产数据清理。

## Evidence Boundary

- 本地验证不等于生产已部署；上线后需使用真实筛选 URL 和测试记录进行受控回归。
