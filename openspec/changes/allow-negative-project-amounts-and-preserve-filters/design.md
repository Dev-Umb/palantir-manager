# Design

## 项目数值范围与精度

项目字段元数据移除七个金额字段的 `min=0`，保留 `weight`、`signed_weight` 的非负规则和 `payment_progress` 的 `0–100` 规则。控制器不再为所有项目数字追加全局 `min=0`。

`CreateObjectRecord` 在所有项目创建和更新写入路径共用的 `normalizePayload` 中，根据项目元数据定位 `type=number` 字段。非空有效数字使用 PHP `round(value, 2)` 归一化；空值保持空，验证层继续拒绝非数字。这样网页表单、列表内编辑和其他既有项目写入路径口径一致，且不扫描或回写历史记录。

前端根据对象键为项目数字输入使用 `0.01` 步长，列表和详情使用固定两位小数格式。编辑器仍提交原始输入，由服务端作为精度权威。

## 筛选状态保持

项目主档列表的查看和编辑链接先携带当前搜索、筛选、排序及分页参数，仅追加弹窗所需的 `record` 与 `mode`。编辑弹窗再通过 Inertia PUT 提交经校验的项目列表 `return_to`，非 JSON 更新成功后由控制器返回该筛选、排序和分页 URL，而不是固定的无查询参数对象列表。控制器只接受当前对象的相对列表路径，避免开放重定向。JSON 列表内编辑仍返回 JSON，不触发导航。

## 非目标

- 不改变内联编辑的乐观更新/失败回滚机制。
- 不改变筛选条件本身或小计计算逻辑。
- 不对历史值执行批量格式化或修正。
