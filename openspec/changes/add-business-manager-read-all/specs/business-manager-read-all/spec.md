## ADDED Requirements

### Requirement: 指定账号全量查看现有业务数据

系统 MUST 为获授业务管理查看角色的武全明账号开放当前业务工作区全部业务数据的读取能力，并保持其他账号原有范围。

#### Scenario: 读取他人业务数据

- **WHEN** 目标账号使用既有列表、搜索、详情、经营汇总、导出或附件读取入口
- **THEN** 系统 MUST 包含他人业务记录并保持各入口范围一致，且不得因此开放账号及权限管理

#### Scenario: 普通业务员继续访问

- **WHEN** 未授予本角色的业务员读取项目、客户或联系人
- **THEN** 系统 MUST 保留该账号原有的业务范围，不受本次目标账号赋权影响

### Requirement: 查看能力不能扩大写入权限

目标账号的写入 MUST 同时满足本人归属和原有对象、字段、操作权限；新增角色 MUST 不提供额外写权限。本人项目 MUST 按负责业务员判断，共享于他人项目的客户主档 MUST 保持只读。

#### Scenario: 修改本人负责项目

- **WHEN** 目标账号更新负责业务员为本人的项目，并提交原有可编辑字段
- **THEN** 系统 MUST 按原规则保存并保留审计，财务专属与系统字段仍受原有限制

#### Scenario: 直接请求修改他人记录

- **WHEN** 目标账号通过保存、删除、内嵌维护、关联变更或现有 AI 确认入口尝试改变他人业务数据
- **THEN** 系统 MUST 拒绝写入，数据和相关业务副作用保持不变，不产生成功写入审计

#### Scenario: 知会与历史创建不等于本人归属

- **WHEN** 目标账号仅为知会人或创建人，或项目已转交其他负责人
- **THEN** 系统 MUST 允许查看但拒绝修改该项目

#### Scenario: 共享客户与无归属记录

- **WHEN** 目标账号尝试修改同时关联他人项目的共享客户主档及联系人，或无法证明本人归属的记录
- **THEN** 系统 MUST 保持记录可读但拒绝通过本角色获得写入能力

#### Scenario: 通过关联字段越权

- **WHEN** 目标账号在本人记录中提交会改动他人项目或主档的关联变更
- **THEN** 系统 MUST 拒绝越权影响，不能因关联对象可读而允许写入

### Requirement: 角色生命周期与页面行为一致

系统 MUST 对已核实的唯一账号赋权并审计，保持权限在元数据同步后有效；页面操作状态与服务端最终权限 MUST 一致。

#### Scenario: 他人记录的页面呈现

- **WHEN** 目标账号查看他人记录
- **THEN** 页面 MUST 保留数据并明确呈现只读状态，不提供可成功执行的写操作

#### Scenario: 角色冲突或撤销

- **WHEN** 目标账号存在可放行他人写入的其他角色，或本次新增角色被撤销
- **THEN** 赋权流程 MUST 在生效前明确解决冲突，撤销后 MUST 恢复原业务读取范围，不静默删除其他角色或改写业务数据

#### Scenario: 其他管理角色不受影响

- **WHEN** 未参与本次赋权的管理员或财务账号操作既有业务入口
- **THEN** 系统 MUST 保持其现有记录与字段权限
