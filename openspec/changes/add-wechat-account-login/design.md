## Scope and capability mapping
| 现有能力 | 实施后的入口与行为 |
| --- | --- |
| 小程序密码登录 | 明确退役该界面；替换为微信登录与首次绑定码输入 |
| 后台与其他客户端密码登录 | 原入口和接口保留 |
| 账号设置的邮箱与密码维护 | 保留；新增微信绑定状态、生成绑定码、解绑 |
| 管理员角色分配、密码重置、账号删除 | 保留；增加受 rbac.manage 保护的微信解绑 |
| 小程序退出登录及失效清理 | 保留；微信登录复用相同会话与缓存隔离 |
| 业务权限和数据范围 | 完全复用原账号，不授予新角色 |

## Identity and binding
- 以 (appid, openid) 唯一识别微信身份；每个账号在本 AppID 下最多绑定一个微信。数据库唯一约束和事务处理并发，不按昵称、手机号或可选 UnionID 自动合并账号。
- 微信 code 由服务端交换验证，不接受前端直接提交 OpenID 或 session_key。密钥及微信响应敏感字段不记录，不回传。
- 绑定码采用加密安全随机值、仅存哈希、10 分钟有效、一次使用；重新生成立即废止旧码。生成接口要求有效后台会话、CSRF 和限流，并复核当前账号密码；小程序不输入平台密码。
- 绑定确认界面不提前泄露目标账号信息。成功消费绑定码与写入绑定在同一事务内完成；已被其他账号绑定时拒绝并要求先解绑，不转移身份。
- 微信登录成功重建会话；未绑定、账号已删除、上游异常、配置缺失、无效/过期/重放凭证均不得建立登录态。
- 解绑后停止该身份后续登录，并撤销该绑定建立的小程序会话；后台与其他客户端会话保持。通过绑定版本/标识校验处理解绑后已有小程序会话。
- 自助解绑要求密码复核及明确确认；管理员解绑使用现有 rbac.manage 权限并明确确认。审计记录操作者、目标账号、绑定/解绑动作，不记录绑定码、密钥、完整 OpenID。

## Rollout
先本地假微信响应测试，再质量检查、PR 合并、迁移和服务端配置，最后由用户手机验证真实微信身份。未完成配置时展示准确的暂不可用提示，避免按钮无反馈；不以关闭域名校验作为交付。
