## ADDED Requirements

### Requirement: WeChat-only mini program login
The mini program SHALL authenticate existing accounts through server-verified WeChat identity and SHALL NOT expose an account password login form.

#### Scenario: Bound identity logs in
- **WHEN** WeChat verifies a login code whose identity is bound to an active platform account
- **THEN** the server regenerates the session with that account's existing permissions and data scope

#### Scenario: Unknown identity or upstream failure
- **WHEN** an identity is unbound, deleted, invalid, or cannot be verified
- **THEN** no authenticated session or account is created and the client displays a specific recovery action

### Requirement: Verified account binding
The system SHALL bind a verified WeChat identity using a short-lived single-use code generated by the authenticated account owner after password re-verification in the web backend.

#### Scenario: First mobile binding
- **WHEN** a verified WeChat identity presents a valid unused binding code
- **THEN** the server atomically consumes the code and binds the identity to the issuing account without accepting a client-selected user id

#### Scenario: Conflict and replay
- **WHEN** a code is expired, superseded, reused or concurrently consumed, or either account or identity is already bound incompatibly
- **THEN** the operation fails without transferring identities or changing existing permissions

### Requirement: Binding management and revocation
The backend SHALL expose binding state and confirmed unbinding to the account owner and authorized administrators while retaining all existing account-management capabilities.

#### Scenario: Unbinding
- **WHEN** the owner re-verifies their password and confirms unbinding or an administrator with rbac.manage confirms unbinding
- **THEN** the binding and associated mini program sessions are revoked and a non-secret audit event is recorded

#### Scenario: Adjacent clients and permissions
- **WHEN** WeChat binding or login is used
- **THEN** browser and other client password login, account settings, role management and unrelated sessions remain functional and no business permissions are granted

### Requirement: Server-side credentials
The system SHALL keep AppSecret and WeChat session keys out of client code, logs and responses and SHALL validate identity through the WeChat server.

#### Scenario: Missing configuration
- **WHEN** the server lacks valid WeChat configuration
- **THEN** the UI accurately reports unavailability and never falls back to a fabricated identity or administrator login
