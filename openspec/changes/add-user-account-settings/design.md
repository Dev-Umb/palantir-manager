## Context

已核对当前工作区及 `codex/finance-project-dates` 的认证代码。登录使用 `users.email`，密码以哈希保存；现有注册最短密码为 8 位。当前代码没有初始密码状态字段。演示 seed 使用公共演示密码，管理员创建命令接受调用者提供的密码，不能据此确认生产账号分配规则。

`codex/finance-project-dates` 的认证控制器保留业务员登录进入项目页的规则；当前工作区另有大量未提交改动，因此不直接在旧认证基线上替换实现。

## Decisions

- 入口为左侧“用户设置”，内容为独立设置页面；移动端通过既有“更多”导航访问。
- 登录账号字段继续使用邮箱。邮箱与密码使用独立表单，防止只改邮箱时意外修改密码。姓名只展示，不扩大可编辑范围。
- 服务端始终以当前认证用户为目标，不接受客户端提供目标用户 ID。校验只允许明确字段，保持角色和业务关联不变。
- 修改邮箱要求当前密码、合法邮箱、唯一性；真实邮箱变化清除原邮箱验证时间，不改变现有邮箱验证流程。
- 修改密码要求当前密码、新密码及确认；新密码至少 8 位且不能与当前密码相同。保存成功才解除初始密码提醒，并清空前端密码输入。失败不修改任何账号状态。
- 保留当前会话，更新会话 ID 和 remember token；不在本次引入全局会话中间件或强制所有设备退出的策略。
- 提醒使用全局 Layout 中的可见提示，文案见下文已确认决定并提供“修改密码”入口。保留正常登录跳转和业务操作。
- 客户端只接收是否提醒的布尔值，不接收密码、密码哈希或用于匹配初始密码的材料。密码不写入日志、历史表单状态、Git 或文档。

## Confirmed Decision (2026-09-08)

用户确认所有初始密码相同，并明确授权按账号布尔标记统一要求改密。字段采用 `is_password_changed`，数据库与模型默认 false；新账号也默认 false。迁移给所有历史账号补 false，不识别或保存初始密码。共享属性每次请求读取数据库标记，只有本人成功改密设置 true。修改邮箱、角色或客户端夹带该字段均不能清除提醒。

管理员在既有“用户与权限”页展开目标用户的重置表单，输入自己的当前密码及给目标用户设置的临时密码（两次确认、至少 8 位）。使用现有 `rbac.manage` 权限，重置密码与标记 false 及无密码审计在同一事务内保存；轮换 remember token。CLI 管理员重置流程也恢复 false。不会自动发送或回显密码，不重置角色、不删除用户。

提醒文案改为“为保障账号安全，请修改密码。修改完成前将持续提醒。”，不声称服务器比对过初始密码。提醒不强制跳转，不阻断业务。当前已登录会话不批量注销；新凭据与 remember token 在更新后生效。

## Validation and Rollback

- L2：未登录拒绝访问、各角色维护本人账号、正确/错误当前密码、邮箱格式和占用、密码确认和最短长度、不能改成当前密码、失败无部分写入、更新后使用新凭据登录。
- L2：目标用户 ID/角色夹带无效，用户 ID、角色、业务归属及登录落点保持；标记 true 不提醒，标记 false 提醒，改密成功解除、失败保留，记住登录的恢复路径适用。
- L2：管理员重置需权限及操作者密码，失败不改目标密码或状态、不写成功审计；成功恢复 false、旧凭据失效、本人改密后恢复 true。
- L3：管理员展开/取消/提交重置、错误反馈、成功清空敏感输入，保留角色保存与删除用户边界。
- L3：桌面和移动端入口、两个表单的提交与错误反馈、成功清空密码、提醒入口、无提醒状态，以及业务导航和退出功能保持。
- 必须验证初始状态不是仅一次性 flash，跨页面和重新登录仍遵循真实账号状态；重新向服务端加载页面后读取最新标记。
- 运行严格 OpenSpec 校验、相关后端与前端测试、PHP 格式化及完整质量门禁；本地验证与上线证据分别记录。
- 回滚恢复原入口和认证扩展代码，不恢复旧密码，不覆盖用户已保存的登录邮箱；迁移 down 仅删除新增标记列，不恢复旧密码或旧邮箱；重新应用迁移会重新要求所有账号改密。
