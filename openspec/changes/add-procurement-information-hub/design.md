# Scope contract
- 必须改变：独立信息中心、四类 Agent、证据数据和审计。
- 必须保持：ERP 业务数据、权限、接口、通知和流程。
- 允许隐藏：无权限管理入口、未审计的正式推荐。
- 必须可见：原文、时间、价格口径、推荐依据、缺失和状态。
- 禁止推断：无记录即未合作、候选人即中标人、推荐分即中标概率。

# Design
hub 数据持久化仍独立。新增只读项目投影，仅查 BusinessObject 的 project 标识及 ObjectRecord 中对应项目行，白名单取名称、编号、阶段、备注、交付日期、预估重量；不解析客户关系或合同、财务、通知。管理员可见全部项目，业务员仅自己的项目，其他无项目读取权限的账号仅使用公开信息。共用用户及角色。访问限 admin/tender/business；管理限 admin。Hub 页面跳过 ERP 导航和通知数据查询，仅提供返回主平台入口。
来源→安全 HTTP/附件抓取→已验证来源的保守字段提取（模型不可用时公告仍可用）或采集 Agent 结构化提取→程序证据校验→公告→分析→推荐→独立审计。模型只获得本模块输入，无 ERP 查询或写入工具；推荐调用仅接收程序提供的授权项目投影。提示注入视为不可信原文，所有输出须校验。
每一步单独排队和持久化。单次模型调用限制时间；自动修正最多两轮。技术异常重试与业务修正分开。取消、失效、重复执行、发布均由事务和条件更新约束。
按公告版本与账号可见项目投影版本生成输入快照。发布前重新校验版本；变更使历史报告标记过期，保留报告及证据。跨站转载以已证实项目编号、采购主体、包件、轮次与公告阶段识别，无足够键不自动合并。
统计由代码计算；金额类型、单位、规格、税、运、租赁期限不同不混合。只发布带有效证据的结论，不生成中标概率。资料缺失时返回限制。
先验证中铁鲁班、中国化学、安徽建工各10条样本；无法访问明确记录为未验证，不用模拟数据替代真实验收。付费接口不自动购买。

# Rollout and rollback
迁移只新增 hub 表。已验证来源首次初始化自动启用，已有来源启停状态保持；未知候选仍需管理员验证；队列工作进程和计划任务须正常运行。停用来源可停止采集，回滚新迁移不触碰 ERP。生产部署不属于本轮自动执行范围。

# Validation
L1 价格可比性与证据规则；L2 权限、持久化、任务及 ERP 隔离；L3 页面渲染交互；真实来源样本单列证据。OpenSpec 严格校验和最终 quality:gate。

# Simplified experience (user-approved revision)
首页默认推荐，保留关键词搜索，地区/类型/历史/排序折叠到更多筛选。初筛明确标为公开信息或项目关键词初筛，有逐条理由、参考项目、限制；它不是审计通过的 AI 结论，也不是中标概率。深度分析自动排队、去重并有冷却，原结果更新状态可见。独立企业资料不再作为分析输入或前置条件。
用户项目输入与报告绑定 user_id，其他用户和匿名市场任务不可读取；访问和发布时重新核对项目投影版本及权限，过期私人输出隐藏并自动更新。AI 引用项目必须匹配快照 ID 与原字段短句，项目存在不代表投标/中标。

# Existing capability mapping
- 公告与推荐列表 → 首页默认推荐，全部公告仍可筛选，详情不变。
- 研究条件和历史任务 → 次要“专题研究”入口；详情自动分析保留手动重试/取消。
- 收藏订阅 → 我的关注。
- 独立企业资料及导入 → 管理后台的旧资料入口，保留历史数据，不再要求填写或供推荐使用。
- 来源、Agent、审计 → 管理员高级维护入口，普通浏览不出现配置任务。
- ERP 项目主档 → 只读必要字段作为辅助证据，不新增编辑入口、不读关系表、不更改原权限。

# Initial online-data review and local reports
用户追加授权直接读取线上项目主档、替其完成信息中心方向配置。2026-09-10 使用数据库只读事务取得 332 条项目必要字段，未查询客户、合同、财务等其他对象，未修改线上 ERP。预览使用临时只读投影快照，原始私人数据不写入仓库。根据主档收窄至模板/台车/挂篮、桥梁钢结构、护栏预埋件、梁场下构；无需用户配置。

首页与详情直接提供程序生成的原文和主档核对报告，明确它不是已审计的 AI 推断。已结束公告只供历史研究，转载缺失字段保持未知，主档“未中标”备注作为反例保留。项目数据外发到外部 AI 目的地当前未获明确授权：程序默认阻止含项目投影的模型调用，允许本地核对和公开数据采集。`HUB_ALLOW_PROJECT_AI` 仅可在获得相应目的地授权后由运维启用，不作为业务用户配置步骤。

# Approved pilot rollout (2026-09-10)
用户明确授权项目主档必要字段发送到平台现有 Aimon，指定 gpt-5.6-luna、低推理强度，要求试部署线上及每 12 小时更新。本模块独立指定模型，不改变 ERP 现有 AI 默认配置。报告增加证据支持的匹配点、资格缺口、反例、预算/候选报价/成交价/租赁口径对照及报名窗口和行动清单。

使用已授权目的地的现有凭据，不落盘新密钥。主档按可见范围选取相关项目（最多 20 条，保留反例），外部证据按项目优先裁剪（最多 10 份）；模型输出有上限，未变化输入不重复调用。来源每 720 分钟更新，计划每天 00:00 和 12:00（Asia/Shanghai）触发，取消原 15 分钟采集触发。部署仅包含 hub 文件与现有共享入口的必要合并；保留线上其他模块和当前工作区未提交修改。先备份、检查精确发布包并验收，再启动独立队列和定时任务。

### 试运行接口与引用验证补充

实测 Aimon 的 `gpt-5.6-luna` 在 Chat Completions 接口可用，Responses 接口返回 400；信息中心通过独立 HubChatGateway 接入已有 Aimon 凭据，不改变平台默认 provider/model。调用使用 low reasoning、store=false、3500 输出 token 上限和 60 秒超时。

为减少小模型抄写错误，报告 Agent 选择程序从原文切出的固定片段编号；程序解析为原文和证据 ID。未知编号不能发布，审计仍独立检查结论与原文是否实质一致。推荐阶段使用临时项目短编号，程序仅映射到本次授权快照中的真实 ID。内部历史反例使用可验证的项目字段引用，不强迫添加无关的外部公告引用。先执行引用预检；不合格时不消耗审计模型调用，最多仍只纠正两轮。

统筹只接收每份证据前 1000 字；分析与推荐保留目标正文前 6000 字、其他正文前 2000 字。审计读取目标正文和其他引用的真实上下文。前阶段的重复引文不重复发送。已在 12 小时内检查的来源不因每份报告再次爬取。报名截止与投标截止分开提示，已报名者的递交窗口不能被描述为可新报名。

推荐输入进一步限定为有明确产品关键词的主档及可核验的未中反例，上限 20 条，不用无关项目填满名额。内部引用同样使用程序绑定的 project_key，避免小模型抄错字段名或长编号。只读项目主档不能确认法定资格，当前版本不生成无依据的数字评分；以有条件的文字建议和已保留的关键词排序呈现。
