# Design: 项目名称作为排序分组键

## 服务端排序

复用 `OntologyController::applySort()` 作为列表与导出的排序权威：

- 项目主档未提供有效 `sort` 时，移除初始最近更新时间排序，改为 `title ASC, id ASC`。
- 项目主档选择对象 `title_field` 以外的有效字段时，先执行 `title ASC`，再执行所选字段及用户方向，最后以相同方向的 `id` 稳定排序。
- 项目主档选择对象 `title_field`（当前为 `name`）时，不额外添加固定升序，直接尊重用户对项目名称的方向。
- 非项目对象保持现有逻辑。

项目名称使用记录的 `title` 列。它是项目名称的既有持久化快照，避免在 JSON payload 上增加新的表达式排序和数据迁移。

## 前端文案

项目主档排序下拉框的空值选项显示“默认（项目名称）”；其他对象仍显示“默认（最近更新）”。空值仍不提交 `sort` 参数，由服务端决定项目默认排序。

## 非目标

- 不新增数据库字段或索引。
- 不改变项目名称编辑、去重或导入规则。
- 不改变筛选结果小计的计算口径。
