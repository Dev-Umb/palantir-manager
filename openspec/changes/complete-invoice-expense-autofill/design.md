## Decisions
复用现有识别字段和费用 items JSON。invoice_date 为可选 YYYY-MM-DD，后端严格验证实际日期；旧客户端省略字段仍可提交。金额仍以整数分处理。缺失值不覆盖人工输入，覆盖已有金额/日期前展示新旧值，由现有核对操作确认。说明追加当前发票有效非金额/日期字段，重复应用不重复追加；超过现有 500 字限制时提示人工整理，不静默截断。

一份单票文件对应新费用项，不对 PDF 进行自动切页识别。新增附件只复用没有附件/失败任务的空白项，否则新建项；上传失败重试沿用原项。旧版多附件项在历史与重提时原样保留，不猜测分摊；新添票据进入独立项。50 项、每项/总附件大小限制保持；已满时上传前提示，不丢文件引用。

客户端总耗时与服务端阶段耗时分开测量。上传完成和识别完成分开呈现。服务端只为报销入口启用计时，不把全局业务附件变更混入此需求；需要复用存储内部时通过不改变默认行为的观测入口测量对象存储写入/校验。诊断不得通过删除 SHA256 校验提升速度。

## Capability Mapping
| 现有能力 | 改动后入口/行为 |
| --- | --- |
| 添加发票 | 第一张可复用空费用，后续新建独立费用 |
| 金额核对回填 | 核对并填入费用信息，金额、日期、说明分别映射 |
| 手写说明与金额 | 保持可编辑，不静默覆盖 |
| 失败重试、附件移除 | 保留在原费用项，不重复建项 |
| 驳回重提 | 保留旧项数据与附件，新票单列 |
| APP/小程序/PC 详情 | 均显示保存的日期、金额、说明 |
| 私有附件、审批、知会 | 现有权限、路由和行为保持 |

## Rollout and Risks
先兼容后端字段，再发布双端；旧客户端不传日期仍有效。历史 items 无日期时只在展示层兼容，不回填历史数据。回滚客户端不会删除新增服务端字段。真实性、OCR 精度和多票 PDF 自动拆分不在范围内。

2026-10-29 只读检查：服务器 load average 约 0.08/0.06/0.02，可用内存约 1 GB；最近日志中的两次上传均 201，识别分别 419 和 200。无 request_time/upstream_response_time，不能据此推导带宽峰值。增加带宽的建议需基于同一请求的文件大小、客户端传输、存储写入/回读、识别耗时及对应网络利用率；本提案不授权采购。

用户后续确认：去除附件下方识别结果列表，识别完成自动打开核对对话框；多张发票的弹窗串行。优化费用表单字体、行距、输入框内边距，金额与日期双列，附件操作区紧凑呈现，不改变保存和审批逻辑。
