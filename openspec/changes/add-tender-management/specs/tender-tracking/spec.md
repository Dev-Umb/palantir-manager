## ADDED Requirements

### Requirement: 招投标信息登记与状态流转

系统 SHALL 提供 `tender`（招投标信息）业务对象，复用本体架构与客户主数据，承载从「跟踪中」到「已中标 / 未中标 / 已放弃」的完整状态，且不得修改任何已有业务对象的定义。

#### Scenario: 招投标专员登记新标讯

- **WHEN** 具有 `tender` 角色的用户创建一条招投标记录，填写标的名称、关联客户（可选择已有客户或现场新建）、信息来源与三个精确到分钟的截止时间
- **THEN** 系统 MUST 生成 `ZB` 前缀编号并保存记录，客户字段 MUST 引用与项目主档共用的 `customer` 主数据

#### Scenario: 招投标专员维护前期客户

- **WHEN** 具有 `tender` 角色的用户查看、新建或编辑客户
- **THEN** 系统 MUST 允许操作并写入既有客户主数据；删除客户 MUST 被拒绝，且已有角色的客户权限 MUST 保持不变

#### Scenario: 现场输入新客户名称

- **WHEN** 招投标专员在客户关联字段输入一个不存在的客户名称并保存 tender
- **THEN** 系统 MUST 在同一业务事务内创建客户、记录审计并将 tender 关联到新客户；精确同名客户已存在时 MUST 复用而非重复创建

#### Scenario: 无权限角色不可见

- **WHEN** 不具有 `tender`/`business`/`admin` 角色的用户访问招投标列表或记录接口
- **THEN** 系统 MUST 拒绝访问，且该对象不得出现在其导航与对象清单中

#### Scenario: 已有对象定义保持不变

- **WHEN** 招投标对象上线后读取 `project`、`customer` 等既有对象定义
- **THEN** 其字段、角色与权限 MUST 与变更前完全一致

### Requirement: 招投标附件管理

招投标记录 SHALL 支持招标文件与投标文件扫描件两类附件，复用既有附件能力。

#### Scenario: 上传投标文件扫描件

- **WHEN** 招投标专员在记录上上传投标文件扫描件
- **THEN** 系统 MUST 通过既有附件通道保存并在记录中可见，不得引入新的存储机制

### Requirement: 投标率统计数据可聚合

招投标记录 SHALL 以关联客户与终态状态支持按客户维度的投标次数、中标次数、中标率聚合，本期保证数据完备，统计视图列为后续阶段。

#### Scenario: 按客户聚合并口径一致

- **WHEN** 对招投标记录按 `customer_id` 分组统计
- **THEN** 状态为「已递交 / 已中标 / 未中标」的记录 MUST 计入投标次数，「已中标」MUST 计入中标次数，「跟踪中 / 已报名 / 已购标书 / 制作中 / 已放弃」MUST NOT 计入投标次数
