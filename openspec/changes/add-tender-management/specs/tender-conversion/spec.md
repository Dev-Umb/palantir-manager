## ADDED Requirements

### Requirement: 中标人工确认流转

系统 SHALL 提供由招投标负责人人工触发的「确认中标并流转」动作，流转时 MUST 人工选择接手业务员，系统在事务内更新招投标状态、创建项目主档记录并回写关联，不得自动流转。

#### Scenario: 确认中标并指派业务员

- **WHEN** 具有 `tender` 或 `admin` 角色的用户对一条未流转的招投标记录执行「确认中标并流转」并选择一名 `business` 角色用户
- **THEN** 系统 MUST 在单个事务内将该记录状态置为「已中标」，创建继承客户与标的名称为项目名称的项目主档记录、以被选用户为业务经理，并在招投标记录回写 `converted_project_id`

#### Scenario: 未选择业务员不得流转

- **WHEN** 执行流转动作但未提供接手业务员
- **THEN** 系统 MUST 拒绝执行且不产生任何状态变更或项目记录

#### Scenario: 重复流转被拒绝

- **WHEN** 对 `converted_project_id` 非空的招投标记录再次执行流转
- **THEN** 系统 MUST 拒绝并返回既有项目引用，不得创建第二个项目

#### Scenario: 通用编辑不得直接写入已中标

- **WHEN** 任一用户通过通用 tender 创建或编辑接口提交状态「已中标」
- **THEN** 系统 MUST 拒绝请求且不得变更记录；只有本流转动作可写入该状态

#### Scenario: 并发流转至多创建一个项目

- **WHEN** 两个获授权请求同时流转同一 tender
- **THEN** 系统 MUST 通过事务行锁保证只创建一个项目，另一个请求 MUST 返回既有项目引用而不得重复创建

### Requirement: 流转通知与审计

流转完成 SHALL 通过 tender 站内通知通知接手业务员与全部管理员，并写审计日志。

#### Scenario: 业务员与管理员收到通知

- **WHEN** 流转事务提交成功
- **THEN** 接手业务员与每个 `admin` 用户 MUST 各收到一条流转通知，通知 MUST 包含招投标记录与新项目的关联入口，审计日志 MUST 记录操作者、招投标记录与项目引用

### Requirement: 项目主档定义不变

流转创建的项目 MUST 使用既有 `project` 对象定义与通用创建路径，不得为流转修改或扩展项目对象字段。

#### Scenario: 流转项目与手工项目等价

- **WHEN** 流转生成的项目记录被既有项目相关功能（列表、详情、通知、财务同步）读取
- **THEN** 其行为 MUST 与手工创建的项目完全一致
